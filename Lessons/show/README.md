# Сервис заказов — занятие 9

Готовый пример API-контракта и Swagger UI. Требуется Go 1.22 или новее.

## Запуск

Откройте папку `show` в IDE или перейдите в неё в терминале:

```bash
go mod download
go run ./cmd/orders
```

Сервер слушает `127.0.0.1:8080`. Swagger UI: http://127.0.0.1:8080/swagger/index.html.
Запросы для ручной проверки находятся в `requests.http`. Остановка — Ctrl+C.
Данные хранятся в памяти и исчезают после перезапуска.

## API

- `GET /api/v1/status` — статус процесса.
- `POST /api/v1/orders` — создание заказа с телом `{"customer":"Алиса"}` и `Content-Type: application/json`.
- `GET /api/v1/orders/{id}` — чтение заказа по положительному номеру.
- `GET /api/v1/orders` — список, параметры `limit`, `offset`, `status`.

Список возвращает JSON-массив, включая `[]` для пустой страницы. Сортировка по id по возрастанию.
`limit` — 1..100, по умолчанию 20. `offset` — неотрицательное целое, по умолчанию 0.
Фильтр принимает `new` и `cancelled`, но создание назначает только `new`, поэтому фильтр `cancelled` возвращает пустой массив.
Повторные заказы одного клиента разрешены. Успешное создание возвращает 201 и Location.
Ошибки API содержат поля `error` и `code`. Тело создания ограничено 1024 байтами и должно содержать ровно один JSON-объект без неизвестных полей.

## Документация и проверки

Готовые файлы `docs` включены в проект. После изменения аннотаций обновите их и перезапустите сервер:

```bash
go generate ./...
go test -race ./...
go vet ./...
go build ./...
```

Генератор swag v1.16.6 закреплён в go.mod, глобальная установка не нужна.
При первой загрузке зависимостей нужен интернет. Формат документа — Swagger 2.0.
Аннотации описывают API, но не добавляют проверки в обработчики автоматически.

Для сравнения JSON-форм пустых слайсов:

```bash
go run ./cmd/json-shapes
```

Пример предназначен для локального запуска. Постоянного хранилища и авторизации в нём нет.
