# Сервис заказов — пакеты и модули

Учебное приложение на Go. Создаёт заказ с клиентом «Покупатель» и выводит его в консоль.

## Запуск

Команды выполняются из папки `Homeworks/homework_6`, рядом с `go.mod`.

```bash
go run ./cmd/orders
```

Программа создаёт заказ с ID `1` и статусом `new`, затем завершается. HTTP-сервер пока не запускается: сообщение «сервис слушал бы» показывает настроенный адрес.

## Настройка адреса

Переменная окружения `HTTP_ADDR` задаёт адрес сервиса. Если она не задана или пустая, используется `:8080`.

Пример для bash/zsh:

```bash
HTTP_ADDR=:9090 go run ./cmd/orders
```

Пример для PowerShell:

```powershell
$env:HTTP_ADDR = ":9090"
go run ./cmd/orders
Remove-Item Env:HTTP_ADDR
```

## Структура проекта

```text
cmd/orders/main.go
internal/
    config/
    handler/
    model/
    repository/
    service/
```

| Пакет | Назначение |
| --- | --- |
| `cmd/orders` | Точка входа: загружает настройки, создаёт хранилище, сервис и обработчик, связывает их через конструкторы. |
| `internal/config` | Читает `HTTP_ADDR` и подставляет значение по умолчанию `:8080`. |
| `internal/model` | Содержит модель заказа `Order` и ошибку `ErrNotFound`. |
| `internal/repository` | Реализует хранение заказов в памяти: сохранение и поиск по ID. |
| `internal/service` | Проверяет имя клиента, назначает ID и статус нового заказа, сохраняет его через интерфейс `Repository`. |
| `internal/handler` | Передаёт создание заказа зависимости, описанной локальным интерфейсом `orderCreator`. |

Конкретные реализации создаются в `main`. Интерфейсы позволяют заменять зависимости, например передавать другую реализацию сервиса в обработчик.

Данные хранятся только в памяти. После завершения программы они исчезают, поэтому каждый новый запуск начинает нумерацию заказов с `1`.
