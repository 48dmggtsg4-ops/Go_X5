## Что делает программа

Программа отправляет сообщение через два канала: email и push. Каждый канал хранит у себя список отправленных сообщений. Если что-то не так (пустой текст или канал не настроен), возвращается ошибка, а в консоль её печатает уже main.

## Как запустить

Команды запускаются из папки homework_5, версия Go 1.27.1

Запуск программы: go run ./cmd/notify
Тесты: go test ./...
Проверка кода: go vet ./...
Проверка форматирования: gofmt -l practice/tasks.go cmd/notify/main.go (если ничего не вывело, всё ок)

## Настройка

| Параметр | Переменная окружения | Значение по умолчанию |
|---|---|---|
| Адрес HTTP | `HTTP_ADDR` | `:8080` |

Запуск с другим адресом:

```bash
# zsh/bash
HTTP_ADDR=:9090 go run ./cmd/orders
```

```powershell
# PowerShell
$env:HTTP_ADDR = ":9090"
go run ./cmd/orders
Remove-Item Env:HTTP_ADDR
```

Пример вывода:

```text
сервис слушал бы :8080, создан заказ: {ID:1 Customer:Покупатель Status:new}
сервис слушал бы :9090, создан заказ: {ID:1 Customer:Покупатель Status:new}
```

ID заказа каждый раз равен 1, потому что хранилище находится в памяти и при новом запуске начинается заново.

## Структура и роли пакетов

```text
cmd/orders/main.go       точка входа
internal/config/         чтение настроек
internal/handler/        слой входа, принимает запрос и вызывает сервис
internal/model/          модель данных
internal/repository/     хранение данных
internal/service/        бизнес-логика
```

| Пакет | Роль |
|---|---|
| `cmd/orders` | Точка входа. Читает настройки, создаёт все конкретные объекты (`Memory`, `Service`, `Handler`) и связывает их через конструкторы. |
| `internal/config` | Читает `HTTP_ADDR` из окружения, подставляет `:8080`, если переменная не задана. |
| `internal/handler` | `Handler` получает зависимость через конструктор и знает только метод `Create`, описанный локальным интерфейсом. |
| `internal/model` | Структура `Order` и ошибка `ErrNotFound`. |
| `internal/repository` | `Memory`: хранение заказов в памяти, методы `Save` и `ByID`. |
| `internal/service` | `Service`: проверка непустого имени клиента, выдача ID, статус `new`. Интерфейс `Repository` (`Save`, `ByID`) объявлен здесь. Если `Save` вернул ошибку, заказ не создан и следующий ID не увеличивается. |

Зависимости идут в одну сторону: `main` связывает `handler`, `service` и `repository`, а все три используют `model`. `service` не импортирует `handler` и `repository`.

## Проверенные случаи

1. Успешная отправка. Email и push получили "Заказ готов", ошибки нет, в обеих историях сообщение с префиксом канала.
2. Пустой текст. Dispatch вернул ErrEmptyMessage, истории не изменились.
3. Нет настройки. У push нет DeviceID, вернулась ошибка SendError, в ней видно канал push и причину "не задан device id".
4. Паника в канале. BrokenNotifier упал, но SafeDispatch пошёл дальше. Следующий push получил сообщение "[push] Заказ готов".

## Обработка ошибок

1. Dispatch останавливается на первой ошибке. SafeDispatch не останавливается, он проходит по всем каналам и собирает все ошибки в список.
2. errors.Is используется для проверки конкретной ошибки: ErrEmptyMessage и ErrNotifierPanic.
3. errors.As нужен, чтобы достать SendError и прочитать из неё Channel и Reason.
4. recover стоит в SafeSend, то есть вокруг одного вызова Send. Так паника одного канала не ломает весь цикл, и остальные каналы всё равно получают сообщение.
